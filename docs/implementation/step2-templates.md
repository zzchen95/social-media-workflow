## 6. 可直接使用的对话提示

**选题阶段**

> 读取指定第一步研究目录、已确认账号画像和本轮制作简报，提出3个主选题，分别解释受众价值、原创角度、证据限制、三平台适用性和制作成本。缺画像时只给探索选题，逐条标明假设。不要替用户选择最终方向，也不要编造自有素材、历史表现或个人经历。

**脚本阶段**

> 根据我选定的选题，先写一个主平台的完整拍摄包：两个开场、一份完整正文、连续时间段的分镜、字幕、素材/补拍清单和事实待核实项；再给适用的另两个平台改编。所有内容绑定账号画像和研究快照版本。脚本必须可以照拍，未知信息不得写成事实。

**修改阶段**

> 根据指定版本和镜头反馈修改，保留上一版，列出变更和未解决事项。检查时长、人物、素材及各平台文字是否仍一致。不要把对旧版的确认转移给新版；脚本可拍确认也不代表成品可以发布。


## 7. 演示记录（仅明确授权完整演示时）

新演示在批次中保存 `demonstration.json`，最小约定如下；普通选题不因存在此模板自动展开脚本。`decisions.json` 只收真实用户决定，无真实决定时保持原有空结构；脚本确认保持 null。

```json
{
  "schema_version": 1,
  "authorization": {"user_request_summary": "真实完整演示请求摘要", "recorded_at": "带时区实际时间"},
  "events": [
    {
      "kind": "model_selection",
      "actor": "assistant",
      "recorded_at": "带时区实际时间",
      "target": {"topic_id": "T01", "content_id": null, "version": null, "shot_id": null},
      "text": "代选理由；不是用户选择",
      "expected_effect": "待验证预期",
      "result_version": null
    }
  ],
  "user_quote": null,
  "applies_to_profile": false
}
```

`kind` 另可为 `synthetic_feedback`；反馈目标必须定位输入内容/版本/镜头或段落，`result_version` 记录生成的新版本。类型、操作者和预期不能冒充真实用户意见或效果测量。真实用户之后选择或确认时另记录真实依据，不把演示转换为批准。

旧批次的 `demo_selection / test_stimulus` 等字段按原义读取，不批量迁移，不改历史文件或摘要；不明字段标未知。演示记录只是补充，不改变 `inputs.json`、研究复合引用、manifest 版本/确认及第三步输入契约。
