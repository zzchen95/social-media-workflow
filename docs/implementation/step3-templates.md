再次检查创建新能力记录，不覆盖旧证据；旧 capability-check.json 仍按原路径及摘要消费，不批量改名。可选最新索引不能替代包的固定引用。缺素材时导出/播放留 not_tested；工具可用性描述限定到实际检查环境。


每轮返回新文件、简短变化和待处理项。若用户只说“节奏快点”，可先提出保留重点、减少重复的具体改法并执行已明确部分；不能自行删掉关键事实或把旧版批准带给新版。

没有实际文件时引用为 null，不预填导出名充当成果。批准依据未知时为 null，不生成代替用户的确认。

## 7. 交给第四步及可复用提示

```text
实际使用的平台 / 账号 / 包版本 / 视频与文案摘要：
实际帖子链接或ID / 发布时间与时区 / 信息提供者：
平台内改动及其证据；与原包的差异：
本条实验假设 / 主要指标 / 可比基线或缺口：
D1=实际发布+24小时；D7=实际发布+168小时
实际采集时间、原始指标和数据来源之后补充。
```

**开始制作**

> 读取指定第二步脚本、画像和素材目录，先固定版本并盘点素材，再验证现有剪辑方式。交付源入出点可核对的剪辑表，沿已验证路径导出一个主平台粗剪；没有实际渲染就明确停在哪一步。其他平台先说明适配方案。

**修改**

> 按这个交付包版本和时间码处理反馈，保留旧稿，导出新版并给逐条变更。时长变化时同步更新字幕、声音和相关文案；主题承诺变化则回第二步修稿。不要继承旧包批准。

**定稿**

> 以实际视频整理字幕、封面和各平台发布文字，检查播放、声音、同步与一致性，交付固定文件摘要的整包供我审核。未验证项明确列出，不执行发布。

## 剪映操作与复盘实验的补充字段

使用剪映时按[专项参考](../../.agents/skills/social-content-production/references/jianying-computer-use.md)补充：软件/系统/版本、实际工程定位、能力记录、最后成功动作、当前输入/导出摘要、失败阶段与恢复点。复盘实验另固定 learning_id、next-edit-brief摘要、脚本镜头/稳定片段ID、计划改法、实际执行及偏离；未导出、播放或听校的项保持未验证。
