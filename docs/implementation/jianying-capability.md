# 实际实施剪映的 Computer Use 能力

这是给新 agent 的实施任务，不是已经通过的能力证明。用户要求“实施/跑通剪映能力”时执行本文件；只安装技能、查看进度或修改文档时不操作软件。目标是在当前用户电脑上跑通可恢复的小样和一次修改，再指导用户把它用于真实内容。

## 1. 先接手，再验证当前环境

读根目录 [START_HERE](../../START_HERE.md)、[第三步技能](../../.agents/skills/social-content-production/SKILL.md)和[剪映操作参考](../../.agents/skills/social-content-production/references/jianying-computer-use.md)。完成只读安装/接手检查，保留用户已延期的资料约定；不要把维护者或测试项目的资料当成本机状态。

读取当前可用 Computer Use 技能及其运行、安全和确认规则，验证运行器能否连接，然后只读识别剪映安装/窗口、系统、显示版本、语言及素材路径。只用实际返回的应用和窗口，不能把文档里的接口、软件能力或旧坐标当本次观测。

运行器连接失败时，优先解决项目内可验证的问题；客户端运行器、缺插件、锁屏或权限障碍如实记录并说明需要用户处理的具体一步。不要安装新控制服务、写自制UI驱动、改隐私/安全设置或用终端自动化绕过。恢复次数按当前插件规则执行，持续失败就停在该层，继续不依赖它的准备工作。

## 2. 准备一个独立小样

优先使用用户已提供、允许本地处理的短片段。没有素材但用户要求实施能力时，可用当前已有本地工具生成明确标为合成的短测试片；工具不可用则请用户提供一段短样片，不为此安装软件或上传资料。不得把测试素材记成真实拍摄、用户选题或账号内容。

合成静音片只能验证画面、文字/字幕导入和导出，不能验证人声、听校或ASR。需要验证这些能力时，先看是否已有获准使用的带声音样片；缺少就保留未测试，不用脚本冒充实录。识别入口若涉及云上传或付费，先确认具体素材、目的地及授权，不自动执行。

只创建本次测试需要的目录：

```text
content/tool-tests/jianying/<run-id>/
  capability-check-v001.json
  editor-session-v001.json
  changes-v001.md
media/tool-tests/jianying/<run-id>/
  inputs/
  project/
  exports/
```

路径是组织约定，不预填为已生成文件。测试记录标 `purpose=tool_capability_test`，注明真实/合成输入、执行者及检查范围；不创建虚构业务内容、发布记录或批准。剪映自管草稿不能迁入该目录时，记录实际可恢复定位与依赖，不强改软件设置。个人路径、截图、原片、工程和测试运行记录均留本地，不提交到GitHub。

## 3. 逐项实际跑通

具体UI操作沿剪映参考的“观察 → 一个动作 → 刷新验证”，不固定坐标或假定按钮存在。原片、旧工程和旧导出保留；删除、覆盖及其他需确认的动作按当前 Computer Use 规则处理。

| 能力 | 实施及验收依据 |
| --- | --- |
| 连接与目标识别 | 实际取得剪映目标窗口和新状态；记录软件/系统及未知项 |
| 素材接入 | 导入获准样片，核对显示名称、时长和画面，记录源路径/摘要及检查范围 |
| 基础时间线 | 将素材加入时间线，实际完成分割或非破坏修剪，核对选择、时长与后续轨道变化 |
| 文本和字幕 | 实际增加一处文字；有对齐字幕时测试导入/修改及样式作用域。没有实录或工具就不声称ASR通过 |
| 工程保护与恢复 | 保存独立测试工程/草稿，验证可重新定位和打开；不能只凭自动保存提示判成功 |
| 本地导出 | 确认新输出路径和实际文件，核对非空、摘要、时长、方向及已验证的元数据 |
| 动态与声音检查 | 打开实际导出，记录观看/听校区间、字幕同步及发现的问题；截图、抽帧与音频听校分开 |
| 一轮修改 | 从已保护版本做一个明确改动，保存新工程/导出和变更，验证旧版仍保留、新版变化可见 |

修改测试可用一次字幕改字或非破坏节奏调整；没有用户反馈时明确记为合成测试指令，不能登记为用户要求或批准。时间改变须同步字幕、声音和片段映射。若某项由用户手动完成，记录 `executed_by=user`，不宣称agent已能自动完成该项。

能力记录逐项使用 `tested / not_tested / failed`，保留输入/输出摘要、操作、实际证据、执行者、时间和适用范围。无实际产物的引用为null。只会连接、看图或导出其中一项时只能报告该项；关键环节失败就报告部分能力和恢复点，不能把文档完成或测试代码通过叫“已跑通剪映”。

## 4. 把验证结果变成可复用能力

验证后更新当前环境的能力记录和第三步简报；真实制作包引用确切记录路径及摘要，不引用会变动的“最新能力”。换系统、软件版本、素材格式或运行器后，核对适用范围并重测受影响项，不继承另一台电脑的结论。

需要修改仓库时，把稳定入口、前后检查条件、失败恢复和版本限制写入对应参考；必要时才加入小型可复用脚本及行为测试。不要停在写一份方案，也不要为了展示实施而另造剪辑服务或直接改未验证的剪映内部草稿格式。

共享修改执行：

```bash
python scripts/validate_share.py --full
python -m pytest -q
```

开发依赖按INSTALL安装到本地环境。文件校验与软件实测分别报告；共享的是脱敏方法，真实能力记录不入库。没有用户明确同步/PR请求时保持本地改动，不读取Token，也不因已有Git凭据而推断推送权限。

## 5. 指导用户使用

先用简短中文说明本机哪些项已验证、哪些仍缺，以及现在能交付什么；不要把内部JSON字段变成用户需要填写的长表。

- 首次真实制作，只获取当前必要的主平台、已选脚本和素材位置。资料已延期时先交可做的方案，不反复催填。
- 用户可说“素材在这个目录”“先做一个粗剪”。按第三步固定输入版本，先主平台，再按需要适配另两平台，不默认全跑。
- 用户可说“v001的00:08到00:11太慢”或“只改第二句字幕”。定位到对应预览摘要/片段后生成新版和变化说明，旧版时间码先映射，不静默覆盖。
- 成品交付实际文件、字幕/封面/文案及检查范围。用户明确批准具体账号、平台、整包版本和必要设置后才记批准；本仓库不执行发布。
- 用户提供真实D1/D7数据后，按[留存到剪辑交接](../../.agents/skills/social-performance-review/references/retention-to-edit.md)提出一个可验证改法；无数据只准备分析计划，不编造效果。

每轮结束只给：完成项、实际文件链接、未验证/阻塞项和一个推荐下一步。用户已有明确选择或反馈时继续完成其范围内的工作，不为每个普通动作再询问；涉及当前插件要求的动作确认时，说明具体动作与规则来源。
