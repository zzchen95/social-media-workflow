# 剪辑、字幕与发布包

复用当前 ChatGPT 的对话、文件处理与已验证的本地工具，产出可追溯、可反馈、可审核的制作包。本技能目录向上三级为项目根目录，先读取 AGENTS.md。按需执行，不新增排期、模型 API 或发布适配器，不接入内容发布服务。

## 按任务读取

- 首次制作或调整工作方式，读[第三步流程](../../../docs/implementation/step3-editing-and-delivery.md)，重点是输入、能力小样、剪辑、反馈、审核。
- 盘点、剪辑、字幕、文案或修改时，按阶段使用[制作模板](../../../docs/implementation/step3-templates.md)，不要求一次填完。
- 需要版本变化示例时，读[两轮反馈演练](../../../examples/production.md)。其中素材 ID、时间码、反馈和结果全是假设，不得带入实际素材台账或用户决定。
- 需要改变主题、事实或旁白承诺时，交回同项目 social-content-planning 技能创建脚本新版本；一般裁切和节奏调整只记录制作版本。

## 选择执行范围

如用户决定素材和剪辑软件之后再补，设置或方案阶段不重复索要，不自行安装、登录或启用付费工具。

有脚本但无素材/工具时，完成当前可做的剪辑安排、字幕文本和发布文字草稿，列清假设及待补项；源入出点、实际字幕对齐和导出引用留空。缺少脚本时只交可用模板或交接缺口，不把演练脚本当用户选定稿。尚无真实任务时不预建虚构内容或成品。

将两种状态分开：创作模式为探索/正式，执行进度为方案/粗剪/修改/待审核/完成。缺素材时可以为正式脚本做方案，但不能声称已剪辑。画像或脚本未确认时保持探索；用户明确要求探索粗剪也可执行，但不能标为正式账号发布交付。

## 固定输入与盘点素材

绑定内容 ID、脚本路径/版本/SHA-256、确认依据、画像、研究快照、目标账号/平台/语言及制作简报。不要随“最新研究/脚本”自动换稿；输入变化记录 needs_recheck 与影响。

原片保留原位，给稳定素材 ID，不移动、改名或覆盖。台账按实际取得的信息保存路径、SHA-256、时长、视频与音轨信息、使用范围，以及原始/代理/转码关系与时间映射。Windows 与 WSL 路径分别核实，不能猜测可访问性。

分别记录可定位、元数据已读、抽帧范围、动态观看范围、音频听校范围和用户说明。抽帧/截图不能证明全片运动或声音已检查。用户说有不等于文件已取得；研究参考视频不等于自有素材。音乐和字体使用依据未知时列待确认，不推断平台曲库跨平台通用。

## 验证并采用工具

实际制作前用少量真实素材验证文件访问、信息读取/打开、画面与声音、工程副本保存、小样导出和实际播放，记录环境、工具版本、输出、检查方式、范围及失败点。设计文档中的历史检查不代表当前环境。 能力记录按 `capability-check-vNNN.json` 新增不可变版本，重测、换工具或新增素材都保留旧证据；包固定引用确切路径与 SHA-256。逐项区分 tested / not_tested / failed，写清适用输入/环境；PATH未发现某工具不推断其他系统未安装。旧 `capability-check.json` 按原路径读取，不覆盖或迁移；若有最新索引，索引不能替代旧包固定引用。

优先团队现有编辑器；通过 Computer Use 操作时先读取对应可用技能并验证连接，保持单一操作者。也可用已存在且小样通过的本地工具完成基础处理；有需要再引入轻量处理脚本。不能预设任意编辑器、FFmpeg、转写、字体、原生视频理解或播放能力可用。

工具受阻时保存已完成部分和具体失败点，继续文字/方案或提供给剪辑人员执行；同一失败动作最多再试一次，有新线索才换路径。没有渲染文件不能把命令、工程、JSON 或缩略图当作成片。上传到第三方、付费等新动作先准备可审阅方案，再按实际授权处理。

## 制作与文字加工

默认先做一个主平台粗剪，再做适合的其他平台版本；用户指定范围优先。分别评估小红书、TikTok、Instagram，不把改名或翻译视为已完成适配。

1. 按脚本镜头 ID 匹配实际片段，给稳定片段 ID。剪辑表记录素材 ID、源入出点、成片入出点、轨道、速度、裁切、转场、字幕和声音。每行按平台 + 脚本镜头 ID 对照该平台脚本，动作和计划时段只写该行生效的执行指令；共用素材与跨平台差异另列说明，不夹带其他平台的例外条件。交付前逐行核对动作顺序、是否重复或遗漏；不通过改写上游脚本消除制作表偏差。单位先用毫秒/小数秒，入点含、出点不含；区分脚本计划、源片时间与导出时间。1 倍速简单片段两侧时长一致；变速、叠层、转场及代理偏移明确记录。表格不默认能直接导入编辑器。
2. 缺素材给补拍、删镜头、缩短或替代方案，不用生成内容冒充真实经历。粗剪优先叙事、开场、去重复、基本画面声音及临时字幕，去停顿不得改原话含义。
3. 字幕按实际声音校对，区分转写、翻译、屏幕文字与旁白稿。优先已提供转写或已验证编辑器功能；听不清标待确认，不用脚本填成“已听到”。未对齐时只交文本稿，不伪造 SRT 实测时间。
4. 节奏稳定后对齐实际成片，输出 UTF-8 SRT；按需给 VTT/烧录版。核对否定词、人名、数字、断句、同步、越界、意外重叠和屏幕可读性。声音与画面处理根据实际问题执行；未监听/测量不声称检查通过或达到指标。
5. 封面优先实际成片帧并排版；需要生成/改图时按图像工具技能执行，记录来源，不替换真实事实。发布文字包含各平台账号/语言、封面文案、标题/首句、正文、CTA、相关标签及必要说明，必须与最终视频一致。不虚构链接、商品、数据或效果。
6. 纯文字方案可将官方格式来源/核查日期留 null，并保留导出前待办，不依赖硬编码参数；实际导出前按拟用平台查询必要的当前官方要求，记录来源与日期；媒体交付前验证实际输出符合所选要求。平台曲库、封面选帧、自动字幕等最后设置若未确定，列为待补齐，不扩大审核范围。

粗剪交付附实际文件、版本、时长、检查范围、缺口与需要反馈的重点；用当前可用播放器展示，不承诺聊天一定内嵌播放。只有方案则明确交付的是方案。

## 多轮反馈与版本

反馈绑定内容 ID、平台、包版本/预览 SHA-256、成片时间段或片段/字幕/文案 ID、问题与希望的效果。能明确定位就直接落实；有歧义时仅澄清依赖项，继续其他明确修改。旧版时间码先映射到当前片段，不照旧时间直接删新片。

每轮创建新 bundle，保留父包、工程/时间线、实际导出、字幕、文案、变更清单、逐条反馈状态与未解决项；保留原片及旧稿。时长变化时重排字幕、声音、封面取帧和反馈定位。仅改文案/封面也递增整包，视频可引用原摘要，不必重复编码。

主题或事实变化回第二步修稿；普通节奏调整无需每个剪切重审脚本。跨聊天或断点恢复以文件记录为准，核对最后完成动作与实际输出，避免把重复输出标为新完成。

## 本地档案与检查

遵循流程文档的路径，按当前任务创建必要文件：
- content/assets/<content-id>/inventory-v001.json：实际素材台账；无文件时不伪造素材。
- content/production/<content-id>/brief-v001.md 和 capability-check-v001.json：输入引用、摘要、简报和真实能力记录。
- content/production/<content-id>/bundle-v001/：manifest.json、edit-plan.csv、feedback.json、changes.md、qc.md、platforms/<platform>/copy.md；只保存本轮实际产生的项。
- media/production/<content-id>/bundle-v001/：工程、预览及逐平台视频/封面/字幕。该目录应被 Git 忽略；不向版本库加入真实媒体。

沿用内容 ID，安全且唯一地递增包号。manifest 保存父包、脚本/画像/研究/台账引用、模式/进度、逐平台文件和 SHA-256、所需发布设置、检查、缺口与真实用户决定。尚未生成的文件引用与确认依据为 null，不能预填文件名充当成果。脚本 v001 和制作 bundle-v001 属于不同版本序列。

检查文件非空、可打开/解码、时长/尺寸/方向与计划一致，再检查画面、声音、字幕、遮挡及文案一致性。自动解码/抽帧和全程观看/听校分别记录执行者、时间、方式及范围；用户的明确检查反馈也可记录，不能相互冒充。平台独立保存状态，一处失败不抹掉其他成果。

## 审核与交接

固定审核内容为账号 + 平台 + 包版本 + 视频/封面/字幕/文案等文件 SHA-256 + 必要发布设置。摘要只基于被审核字段，排除批准记录，避免循环计算。关键项完整且用户明确批准具体包后才能记该平台已批准；选题、脚本或粗剪认可不是整包批准。任何项变更产生新版待审核，旧版批准留历史，不转移到新稿。

本技能不发布或改平台账号状态。用户实际发布后，登记帖子、真实发布时间/时区、实际用包和平台内差异；给第四步传递原实验/指标及缺口，D1/D7 以实际发布起算，不编造表现。

普通交付简短说明本轮完成项、方案/实际成片状态、新版本文件链接和未完成项。无法读取、写入或渲染时准确报告，不宣称技能安装等于媒体能力已验证。
