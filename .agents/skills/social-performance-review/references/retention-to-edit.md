# 从发布表现、留存到下一次剪映改法

用于第四步将真实数据落到第二步脚本和第三步制作；没有发布数据时只用作准备清单。指标复盘可以部分完成，精确到镜头的归因需要额外证据。不会自动打开后台、改已发布内容或重剪旧稿。

## 先把三条时间轴对上

1. 固定实际帖子、账号、平台、发布时间、快照版本及数据截至时间；再核对第三步实际发布包/视频摘要和平台端改动。只有用户说明时标用户登记，不冒充平台核验。
2. 固定脚本镜头ID、制作片段ID、源入出点与最终导出时间。剪映工程显示的时间码不是原片或发布端时间；有片头、变速、转场、重发、平台裁切或替换音乐时分别记录映射和差异。
3. 留存图横轴若是百分比，只在实际发布片长已核实时换算秒数；未知片长、图示过粗或版本不符时只谈区间，不捏造具体秒点。比较需同时说明纵轴指标、分母、循环播放及图示精度。

保留以下证据链：`publication → published_video/bundle → snapshot/retention point → exported interval → clip_id/script_shot_id`。任一段缺失就限定结论；无法映射不会阻止描述已核实的总指标，但不能指出“某镜头导致流失”。

## D1/D7的可复算时间

当前解释器执行以下形式，时间必须来自真实记录，不复制示例成为业务数据：

```text
python scripts/review_windows.py --published-at <带UTC偏移的真实发布时间> --timezone <展示时区> --data-through <真实数据截至时间>
```

脚本在UTC加24/168小时，再转展示时区；输出实际年龄及相对容差，默认D1±3h、D7±12h是可调整工作约定。只知发布日期时目标和年龄为null，不假定零点。只知截图采集时间不能冒充数据截至时间；可单独做明确标注的估计，但不能用它覆盖后台截止字段。

脚本只算时间，不抓后台、不创建提醒、不补D1、不给指标或因果结论。保存本次参数/输入引用与输出，报告展示从这份结构化结果生成，不手抄第二份时间。

## 用 Computer Use 查看而不改稿

需要在剪映里核对真实片段时，按第三步 [剪映参考](../../social-content-production/references/jianying-computer-use.md)选择窗口与当前工程；明确本轮是只读检查。只定位播放头、查看时间和必要区间，不剪切、不替换素材、不重生成字幕、不更改已交付工程。若播放会触发工程自动保存，优先可用播放器检查固定导出；不能把原工程状态改变当成无副作用读取。

后台数据默认使用用户提供截图/导出。只有用户明确要求读取指定已登录后台时才按当前工具和权限执行；只记录可见帖级数据与筛选，不登录、发评论、改标题或投流。复盘技能不自动获得后台访问权。

截图能支持画面/文字判断，不能证明音频已监听；粗略留存图不能证明某一帧流失。记录实际观看/听校范围、执行者、时间和未覆盖部分。

## 将观察转成一个可检验变量

| 有效观察 | 可以提出的假设与改法 | 不能直接推出什么 |
| --- | --- | --- |
| 可核对区间留存下降，且实际片段信息重复 | 下条将重复解释缩成一次；固定该镜头ID和保留的事实 | 不能仅凭图证明重复就是原因 |
| 有播放但缺收藏，评论样本提出具体操作需求 | 下条增加一项可执行步骤，先把收藏定义和样本范围写清 | 不能断言算法压流或受众都不喜欢 |
| 单条好于可比样本 | 提出保留某结构的下一次测试，披露中位数、范围及混杂 | 不能确认为永久画像规则 |
| 只有总播放或平均观看时长 | 描述总指标和数据缺口，给探索性创意 | 不能倒推完播率或前三秒流失 |

每轮优先一个变量。改开场信息顺序时保留原核心承诺；若同时换题材、封面、音乐、时长和剪辑，就不能把变化归给单一改法。字幕版式、声音和切点属于制作变量，主题或事实承诺变化先回第二步生成脚本新版本。

在 `next-edit-brief-vNNN.md` 或同一版本化学习简报内记录：

```text
learning_id / 证据报告、快照、字段及摘要：
账号 / 平台 / 实际发布包及视频摘要：
事实 / 原因假设 / 反例 / 未知：
留存区间、坐标单位/精度 / 导出时间映射或不能映射的原因：
原脚本镜头ID / 原片段ID / 下一条目标镜头（未知留null）：
建议只改的变量 / 原状态 / 拟执行动作 / 保留项：
剪映操作意图（如先呈现结果再解释；不保存固定坐标）：
是否改变主题/事实，是否需第二步修稿：
主要指标、分母与D1/D7窗口 / 可比基线或缺口：
预先约定的判断方向 / 约束指标 / 无法控制的条件：
状态：proposed / adopted / implemented / checked；各项真实依据：
对应新脚本、新工程、bundle和实际导出的摘要（未发生为null）：
未解决项 / D7需要保留、修正或撤回的D1判断：
```

proposed是模型建议；adopted须有真实用户决定或其明确授权范围；implemented须有新时间线/文件证据；checked说明剪辑是否按计划实现，不能冒充发布后的效果验证。效果支持、混合或不支持仍沿学习记录另记，不能通过验收导出自动得到。

## 回到第二步和第三步

- 第二步结合适用研究和画像记录 adopted / deferred / not_applicable 及理由；需要用户选题时给少量方向，不替用户选中或静默改定稿。
- 第三步读取固定简报和脚本，将实验变量对应到剪辑表和剪映新工程；交付时核对“计划改什么”和“实际改了什么”，偏离不能掩盖。没有数据时这些只是待验证方案。
- 新包重新检查并交用户批准具体账号、平台、版本、文件摘要和必要设置；随后用户发布，再登记实际T0和表现。不能指示发布后补批，旧包批准不转移。
- D7明确列出对D1的保留/修正/撤回；更新 learning/brief 版本，依赖旧结论的稿标 needs_recheck，不自动重剪或改长期画像。
