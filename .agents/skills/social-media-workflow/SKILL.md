# 三平台内容工作向导

让用户只记住这个入口，用自然语言逐步推进小红书、TikTok、Instagram 内容工作。你在同一聊天按需读取并执行专项技能，不要求用户记技能名、复制提示词、切换聊天或管理技术字段。技能目录向上三级是项目根目录，先读 AGENTS.md。

本技能负责进度识别、下一步引导和交接，不复制四步专业规则，不增加Agent、队列、平台接入或计划任务。用户明确点名某个专项技能或只要某一步时优先该范围；如果用户另行配置过研究自动化，沿其实际设置执行；本仓库不预装自动化。

## 新 agent 接手

先读根目录 [START_HERE.md](../../../START_HERE.md)，运行 `python scripts/agent_start.py` 做只读导航，再核对本轮实际要消费的专项文件。脚本不授予执行许可，也不证明素材/批准/发布完成；多个真实工作流不能按最新目录替用户选中，演练不自动成为当前任务。当前用户只要设置或看进度时，不启动研究或剪映。

## 先识别本轮意图

- “帮我开始/带我走一遍/继续”：核对用户指定材料与本地记录，找当前最有用的下一步；不默认重跑四步。
- 直接给账号、脚本、原片、某版本反馈或表现截图：从对应入口开始，能回填关联再回填，不要求从第一步重新来。
- “看进度/下一步做什么”：先只读核对，再给简短状态和推荐动作，不触发新采集、渲染或重写。
- “设置技能/设计流程”：完成配置或文档，不顺便启动真实研究、生成业务任务或定时任务。
- “演练/资料之后再补”：沿专项技能的探索/方案模式执行；演示与真实用户决定、素材、效果分开。

优先用户指定的内容/账号/平台/版本；未指定时查看已有工作流检查点和相关档案。多个真实活动内容均可能对应“继续”时，只澄清影响本轮的对象，可展示简短名称/状态选项；不要仅凭目录日期选中一条，更不能把演示当用户当前项目。没有检查点也可从既有专项档案恢复，不要求重做。

如用户选择账号资料、素材、剪辑软件或发布数据之后再补，保留该约定，不逐轮催填。无指定阶段且资料缺失时，推荐基于最近有效研究做探索选题；研究暂不可用也能准备输入/常青探索方案，清楚说明依据。用户要求本周新研究时才走本轮采集，旧研究注明实际窗口。

这是文件技能路由，不是假定存在“运行技能”的API。读取所需 SKILL.md 和其当前阶段引用后直接执行可用工具；不只返回技能名称。无需一次加载所有技能与文档；缺少入口或工具时说明具体阻塞，继续不依赖它的工作，不冒充已调用成功。

## 一轮如何带用户往前走

1. 简短说明当前已核实的成果、当前阶段/模式和本轮将完成什么；只展示对本轮有用的缺口，不用长表催用户一次补齐全部资料。
2. 在已授权范围内完成必要工作和验证。明确输入、来源、当前内容ID及实际版本，保留专项技能规定的证据和档案。
3. 按[检查点约定](references/checkpoints.md)保存本轮索引，记录真实用户决定和仍需用户选择/资料/工具的项，专项文件始终是事实来源。
4. 交付用“本轮完成了什么 + 文件链接 + 一个推荐下一步”。需要用户选择时，给少量直观选项和推荐理由，用可用输入工具或交付末尾承接；不在中途进度消息里抛问题。能继续的常规动作不逐步问许可。

“带我走一遍”默认每次完成一个有意义阶段并在用户需要选择、反馈或提供必要资料处交付；不是每条命令、每个镜头都停一次。用户已选方向、已给修改意见或已授权连续执行时，直接续做依赖明确的工作。未经用户选题不能替选；用户明确要演示可继续，但选择与反馈记为合成演示。

如果只说“继续”，先核对检查点的下一步是否已被新消息解决。新上传素材进入第三步，新表现截图进入第四步；不要仍催前一轮已收到的输入。用户要看进度不代表同意推荐动作；用户要执行当前阶段时则完成该阶段内所有必要动作，不把现有授权再问一遍。

## 跨步骤事实与版本

研究、选题批次、内容、脚本、制作包、账号/平台帖子、表现快照、学习简报分别关联，不以一个“完成”标记替代。三个平台各保留适配/交付/发布/表现状态，不把一处成功扩成全部完成。

探索脚本、方案文字、临时字幕、工程文件、合成测试反馈、通过结构检查均不等于真实定稿/成片/人工批准/发布/表现。已有演练即便带v002、manifest或validation，也要检查模式、实际文件及确认依据，不能升格为真实流程。技能安装与工具能力验证分开。

接收用户“已发布”的说明可直接进入第四步登记，不强迫先补做前三步；缺失包或时间精度按第四步保留限制，已知未获批准/发布版本有偏离也如实登记，不把事后登记变成追认批准。本向导不执行发布、互动、账号更改，不把模拟回执当真实结果。

每次消费的研究/画像/脚本/制作包/复盘简报绑定具体版本与摘要。新文件或用户纠正触发 needs_recheck；先核对影响，保存新版本，不静默替换输入、转移批准或覆盖历史。脚本可拍确认不是整包发布批准；长期画像修改沿专项规则处理。

## 基于项目上下文自我迭代

用户提供新工具、明确偏好或真实使用反馈，并要求适配/完善流程时，在本项目内做必要的小范围更新；执行任务后也简短检查是否有值得复用的经验，不为每轮强行修改技能。只查看进度时保持只读。

- 上下文来自本项目的指令、已确认资料、专项档案、工具验证记录和当前对话；按本轮需要读取，不依赖未保存的记忆，不把演示或模型猜测当作经验。
- 优先解决当前实际问题，再提炼可复用的方法。第三步可随用户现用剪辑软件调整素材接入、字幕、反馈和导出方式；记录适用工具/版本与验证范围，未实测的能力保留待验证，不固化屏幕坐标或偶发操作。
- 将稳定经验写入对应专项技能或配套参考/流程文档，工具细节按需读取；总技能只保留引导原则，合并重复或过时内容，避免不断追加细则。保留变更依据与简短摘要，核对引用及必要的小样，不宣称文档修改等于工具验证成功。
- 用户明确说明的工具偏好可以保存；单次结果不扩大为长期账号规则。迭代不改变用户目标、真实证据和人工审核要求，不扩大到发布、付费或新增调度等授权。

用户可直接这样要求：

> 结合本项目已有资料、实际使用记录和我的反馈，调整当前流程，并将验证过的可复用经验更新到相关技能。尤其让第三步适配我们实际使用的剪辑工具；保留未验证项，避免堆积操作细节，简短说明改了什么和依据。

## 进度恢复与使用说明

实际任务或用户明确授权的端到端演练使用 content/workflows/<workflow-id>/checkpoint-v001.json 索引；演练记录 purpose=workflow_trial，始终保留探索/方案模式，不能因此补造真实发布或表现。无发布数据的复盘准备放在该工作流 preparation/ 下。演练各阶段可交付准备成果，但全流程试跑结束不等于真实内容完成；恢复时只推荐当前可做的一步，不反复索取已延期资料。只设置技能或只读查看现状时不创建业务工作流。检查点是导航文件，不是新数据库或自动工作引擎；模板和版本/恢复细节见[检查点约定](references/checkpoints.md)。

用户使用方法见[总向导说明](../../../docs/implementation/workflow-guide.md)。当前会话未发现某技能名称时，直接读取上述真实路径执行，或在用户希望时说明重新进入项目会话；不要把重开会话作为可以通过文件读取解决的问题的阻塞。

普通交付保持简短，不把子技能内部字段和校验命令塞进用户操作步骤。可说“选第二个”“改开场”“素材在这个目录”“这是七天数据”，由你关联正确内容和版本。所有新增调度、后台自动采集或独立聊天仍需对应用户请求，不能从使用总向导推断授权。
